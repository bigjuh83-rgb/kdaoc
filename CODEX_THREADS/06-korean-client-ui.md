# KDAOC/OpenDAoC Korean Client UI Thread

## Scope

- Korean UI font fallback
- `@` replacement glyph issue
- `assets.xml` font aliases
- Gulim/Charset 129
- KoreanGothic.ttf duplicate definitions

## Rules

- Do not touch `game.dll`, glyph warmup, or `0x488b8e` patches unless explicitly scoped.
- Focus first on UI asset font alias conflicts.
- Client full restart is required for verification.

## Known Symptoms

- Not full mojibake.
- Specific Korean glyphs show as `@`.
- Examples:
  - `글자 크기` -> `@자 크기`
  - `하이랜더` -> `하이@@`
- In chat, repeated Korean input can make prior `@@@` replacement disappear in the same client session.
- Korean chat can render normally at first, then show `@` replacement when a mercenary/dummy emits several party-chat lines in a burst.
- Inventory item names/tooltips can show partial `@` replacement for dynamic Korean item text, e.g. random/test item names containing `공격`, `고통`, `검증용`, `잠검`, while other Korean words such as `마력`, `희귀`, or `참격` may still render.
- Likely UI font fallback issue rather than server CP949/game.dll conversion.
- The repeated-input recovery, burst-only chat failure, and partial inventory/tooltip failures point toward dynamic renderer glyph cache/line insertion coverage for dynamic text; do not patch `game.dll` or binary glyph warmup unless explicitly scoped.
