# 용병 시스템 추가 완성 기준

기준일: 2026-06-24

이 문서는 현재 용병 시스템을 더 키울 때 흔들리지 않아야 할 기준을 정리한다. 플레이어에게 보이는 명칭은 `용병`으로 통일하고, 내부 과거 명칭 `companion`은 코드 경계 이름으로만 유지한다.

## 현재 완료된 기준

- 기본 용병은 고용관을 통해 바로 사용할 수 있다.
- 보유 용병은 이름, 직업, 성격, 전술, 친밀도, 피로도, 배경을 가진다.
- 용병은 파티에 실제 플레이어가 들어왔다고 자동 이탈하지 않는다.
- 파티장이 먼저 용병 해산/추방 흐름으로 빈자리를 만든 뒤 플레이어를 초대하는 방향을 기준으로 한다.
- 서비스 장애, 합류 실패, lease 문제, 접속 유예 만료 같은 시스템 사유는 친밀도 불이익으로 보지 않는다.
- 친밀도 불이익은 용병 사망, 방치, 무모한 지시처럼 플레이어 책임이 명확한 사유에만 준다.
- 용병은 `추억`, `일지`, `전술`, `성격`, `초보`, `숙련 운용팁` 같은 자연어 질문에 보유 기록과 전술 기준으로 짧게 답한다.
- 고용관은 `용병 일지` 메뉴로 보유 용병의 추억, 기록, 개인 의뢰, 관계 이벤트를 보여준다.
- 안내/RAG, 인물 대화, 전투 명령은 서로 다른 흐름으로 분리한다.
- 고용관은 처음 하는 플레이어용 `처음 안내`와 오래 한 플레이어용 `운용 팁`을 모두 제공한다.
- 고용관은 선택을 어려워하는 플레이어를 위해 `추천 고용`을 제공한다.

## 획득 구조

v1은 모든 용병을 상점식 목록으로 한꺼번에 보여주지 않는다.

- 계정/캐릭터는 최초 기본 용병 1명을 받는다.
- 이후 용병은 퀘스트, 이벤트, 보스 처치, 운영 보상으로 획득한다.
- 획득 시점마다 용병의 이름, 배경, 성격, 클래스, 전술, 장비 성향을 랜덤 또는 보상 테이블 기반으로 생성한다.
- 같은 보상이라도 플레이어마다 다른 용병 구성이 나올 수 있어야 한다.

권장 데이터 단위:

- `mercenary_source_id`: 획득 출처. 예: `starter`, `quest:forest_aid`, `event:summer_2026`.
- `contract_tier`: 일반, 숙련, 정예, 전설.
- `personality`: 침착형, 생존형, 돌격형, 얍삽한형, 배신자형 등 행동 차이를 만드는 값.
- `tactic_preset`: 안전 우선, 공격 우선, 힐 우선, 메즈 우선, 리더 보호.
- `item_profile`: 실제 보상 아이템 지급이 아니라 용병 성능과 표현에 쓰는 장비 성향.

## 계약과 성장

계약 시작:

- 계약 횟수 +1
- 피로도 증가
- 짧은 친밀도 +1

계약 성공:

- 실제 활동 시간이 길수록 친밀도 증가
- 목표 완료, 보스 처치, 부활 세이브, 리더 보호 같은 명확한 기여는 추가 증가

계약 실패:

- 시스템 문제는 패널티 없음
- 플레이어 책임 사유만 친밀도 감소와 피로도 증가

휴식:

- 피로도는 고용하지 않는 시간 또는 명시적 휴식 메뉴로 회복한다.
- 높은 등급 용병일수록 강하지만 피로도 증가와 재고용 비용도 커진다.

## 자연어 명령 기준

용병은 다음 표현을 모두 명령으로 이해해야 한다.

- 공격: `ㄱㄱ`, `공격`, `같이 쳐`, `때려줘`
- 방어: `방어태세`, `나 지켜`, `보호해`
- 수동: `수동태세`, `공격하지마`, `치지마`
- 대기: `대기`, `멈춰`, `여기 있어`, `움직이지마`
- 추종/소환: `따라와`, `나 따라와`, `붙어`, `옆에 있어`
- 후퇴: `도망쳐`, `위험하면 도망쳐`, `살아서 빠져`
- 상태/기록: `상태`, `친밀도`, `피로도`, `기록`, `활약`
- 일지/운용: `추억`, `일지`, `전술`, `성격`, `초보면 뭐부터`, `숙련 운용팁`

명령은 AI 답변 대기 중에도 즉시 처리 가능한 표현을 우선한다. RAG/자유대화는 전투 행동을 막지 않는다.

## 초보/숙련 UX 기준

처음 하는 플레이어:

- 첫 용병은 치유형을 추천해 안전하게 시작하게 한다.
- `추천 고용`으로 직업/레벨/파티 규모에 맞는 기본 역할을 바로 고르게 한다.
- `상태`, `기록`, `대기`, `따라와`, `ㄱㄱ`처럼 바로 쓸 수 있는 말을 알려준다.
- 사냥터와 스킬 질문을 자연어로 물어볼 수 있음을 안내한다.
- 실제 플레이어 자리가 필요하면 파티장이 먼저 용병을 해산해야 한다고 알려준다.

오래 한 플레이어:

- 치유형, 방어형, 공격형, 지원형의 차이를 바로 확인할 수 있어야 한다.
- 숙련자는 `추천 고용`을 빠른 기본값으로 쓰되, 필요하면 직접 역할을 고를 수 있어야 한다.
- 지원형이 메즈, 스피드송, 보조 유틸 기대 역할임을 알려준다.
- 성격, 전술, 친밀도, 피로도가 실제 운용 차이를 만든다는 점을 보여준다.
- 시스템/서비스 실패는 친밀도 불이익 없이 재고용 가능하다고 안내한다.

## 7명 플레이어 + 용병 1명 검증 기준

운영 전 실제 외부 클라이언트 테스트가 가능해지면 다음을 확인한다.

1. 실제 플레이어 7명이 같은 파티에 있는 상태에서 용병 1명을 고용한다.
2. 8명 파티가 된 뒤 추가 플레이어 초대가 실패하거나, 파티장이 직접 용병을 해산해야 빈자리가 생기는지 확인한다.
3. 실제 플레이어가 접속/재접속해도 용병이 자동 이탈하지 않는지 확인한다.
4. 파티장이 용병 해산을 요청하면 용병이 `/quit` 흐름으로 정상 종료되는지 확인한다.
5. 이 과정에서 친밀도 패널티가 시스템 사유로 발생하지 않는지 확인한다.

현재 자동 테스트는 7명+용병 1명 상태에서 자동 해산하지 않는 케이스를 고정한다. 실제 외부망 게임 클라이언트 접속 테스트는 서버 오픈 전 최종 리허설에서 수행한다.
